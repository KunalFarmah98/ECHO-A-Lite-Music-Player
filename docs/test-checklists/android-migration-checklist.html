Common Smoke Tests (run on at least one device/emulator per ABI)

  • — expected: installs without signature or manifest errors
  • — expected: app opens, no crash, initial screen visible
  • — expected: audio plays, pause/stop works, no skipping
  • — expected: playback continues or behaves per spec (notification + controls)
  • — expected: play/pause/seek respond correctly from notification
  • — expected: route switches, pause on disconnect
  • — expected: permission prompts appear when needed; app handles denial/grant
  • — expected: UI stable; playback unaffected
  • — expected: graceful error or retry; no crash
  • — expected: state preserved, no unexpected restarts
  • — expected: no excessive memory spikes or battery drain during short smoke test
  • — expected: no fatal uncaught exceptions

Comprehensive Tests & Diagnostics

  • Record device/emulator model, Android version/API, build ID, app variant (debug/release), and exact reproduction steps with timestamps.
  • Collect logs and diagnostics for every failure: adb logcat -v time -d > logcat.txt, optionally adb bugreport > bugreport.zip, and dumpsys media_session / dumpsys activity services outputs for service issues.
  • Attach screenshots, short screen recordings, and the failing stack trace or ANR traces. For native crashes include tombstone or adb shell ls /data/tombstones.
  • Database integrity: run migration paths that affect Room schemas; verify data preserved and Room migrations succeed without exceptions. If schema changes exist, include a small export of important tables before/after.
  • Media & playback checks:
    • ExoPlayer / MediaPlayer codec compatibility across API levels; test multiple sample rates and formats (mp3, aac, opus).
    • Audio focus and ducking across calls, notifications, incoming calls, and Bluetooth events.
    • MediaSession controls, metadata, and notification actions (play/pause/seek/stop) — verify media button intents and Car/Android Auto behavior where applicable.
    • Playback under background restrictions, Doze, and app standby (verify scheduled jobs resume correctly).
  • Foreground service & notifications:
    • Verify foreground service starts with proper notification on API 26+; PendingIntent mutability flags applied per API level.
    • Notification channels: presence, importance, tap action, and visibility for locked screens.
    • Notification content and media controls on Android Automotive/TV (if targeted).
  • Permissions & storage:
    • Storage: scoped storage behavior, READ_EXTERNAL_STORAGE -> READ_MEDIA_AUDIO migration, SAF flows, and FileProvider URIs for legacy file sharing.
    • Package visibility: test queries and implicit intents if targetSdk >= 30 (package visibility manifest entries).
    • Runtime permission flows and handling of "deny & don't ask again" cases.
  • Target SDK & behavior changes:
    • PendingIntent mutability flags (IMMUTABLE/MUTABLE) to avoid SecurityException on newer APIs.
    • Network security: cleartext enforcement, TLS versions, and certificate pinning if used.
    • Behavior changes for background execution limits, exact alarms, and system permission restrictions introduced in targetSdk upgrades.
  • UI & platform compat:
    • Edge-to-edge/inset handling and gesture navigation changes (Android 10+). Verify content isn't obscured by system bars or cutouts.
    • Layout integrity on different DPIs, screen sizes, foldables, and multi-window; test rotation and configuration changes.
    • Accessibility: TalkBack navigation, content descriptions, focus order, and contrast checks.
  • Background jobs, WorkManager, JobScheduler:
    • Verify scheduled tasks run with updated constraints and that WorkManager migrations (if any) behave correctly across upgrades.
  • Crash/ANR & performance:
    • Run short stress test (start/stop playback repeatedly, rapid navigation) to surface race conditions and ANRs.
    • Check logcat for fatal exceptions, StrictMode violations, and memory leaks; include trace or heap dump if possible.
  • Build & CI checks:
    • Build variants: debug/release signing, ProGuard/R8 rules, mapping file generation — verify release install and symbolication readiness.
    • Gradle plugin and dependency updates — confirm no deprecation warnings that impact runtime.
    • ABI/testing matrix: run smoke tests on emulators for each ABI (armeabi-v7a, arm64-v8a, x86_64) and in CI if available.
  • Integration & platform features:
    • Deep links / App Links: verify incoming URIs still resolve, and web verification (assetlinks) if used.
    • Widgets, shortcuts, and home screen interactions (if app exposes them).
  • OEM & carrier behaviors:
    • If failures are OEM-specific (Xiaomi, Samsung, OnePlus), capture device settings (battery optimization, special permissions) and reproduction steps.
  • Reporting and triage path:
    • For each confirmed blocker add a TODO in the session with severity, reproduction steps, logs, and a suggested owner.
    • Attach logcat, bugreport, screenshots, and exact git commit/branch in the issue or PR comment.
